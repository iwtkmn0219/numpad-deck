# 3단계 계획: 편집기·온보딩·프리셋

2단계(M2)까지 덱은 동작하지만 버튼을 바꾸려면 JSON을 직접 고쳐야 한다. 3단계는 개발 지식이 없는 사용자가 코드·단축키 문자열·파일 경로를 몰라도 버튼을 만들고, 설치 직후 안내를 따라 첫 버튼을 눌러 보게 만든다.

## 통과 기준 (M3)

1. 개발 경험이 없는 테스터가 앱을 처음 실행한 뒤 5분 안에 안내를 따라 첫 버튼을 실행한다.
2. 그 테스터가 JSON을 보지 않고 버튼의 이름·아이콘·동작(액션 8종 모두)을 바꾸고 새 페이지를 만든다.
3. 단축키는 직접 눌러서 녹화하고, 프로그램은 설치된 앱 목록에서 고른다.
4. 한국어·영어 UI가 모두 완전하다 (트레이 메뉴·OSD·오류 메시지 포함).

설치 파일은 4단계이므로 M3 시험은 개발 빌드로 한다.

## 결정 사항

사용자와 정한 것:

| 항목 | 결정 |
| --- | --- |
| 편집기 배치 | 왼쪽 넘패드 그리드 + 오른쪽 버튼 편집 패널, 위쪽 페이지 탭 |
| 저장 | 자동 저장 (바꾸는 즉시 반영), Ctrl+Z 되돌리기 |
| 아이콘 | Lucide 선 아이콘 (MIT), 검색해서 선택 |
| 프리셋 | 음악·영상, 화상회의, 창 관리·업무, 방송(OBS) |
| 온보딩 | 3단계: ① NumLock 끄기 ② 넘패드 1 눌러 보기(YouTube 열기 — 3-5 시험 후 8 재생/정지에서 바꿈) ③ 프리셋 고르기 + 트레이 아이콘 고정 안내 |

묻지 않고 정한 기본값 (바꿀 수 있음):

- **편집기 여는 법**: 트레이 아이콘 왼쪽 클릭 = 편집기, 오른쪽 클릭 = 메뉴 (Windows 관례). 메뉴에도 `설정 열기`.
- **편집기 창**: 닫으면 파기한다 (상주 메모리 절약). OSD와 같은 WebView2 인자(`--disable-gpu …`)를 쓴다.
- **첫 실행 설정**: 기본 설정을 `음악·영상` 프리셋 한 페이지로 바꾼다 (온보딩 ②에서 1 = YouTube). 온보딩 ③에서 고른 프리셋이 뒤에 붙는다.
- **언어**: Windows 표시 언어를 따르고(한국어가 아니면 영어), 편집기 설정에서 바꿀 수 있다. 설정 파일에 `language` 필드를 둔다.
- **설정 파일 경로·형식**: 그대로. 편집기도 코어의 검증·저장(`config::save`)을 거친다.

## 진행 순서

| 순서 | 작업 | 검증 |
| --- | --- | --- |
| 3-1 | 편집기 뼈대: 창 열기·닫기, 설정 읽기/저장 command, 페이지 탭(추가·이름 바꾸기·순서·삭제), 그리드 + 패널, 자동 저장, 되돌리기 | 편집 → 파일·OSD에 즉시 반영 |
| 3-2 | 액션 편집: 종류별 입력 화면, 단축키 녹화, 설치된 앱 목록, 파일·폴더 고르기, 묶음 편집, `시험 실행` | 액션 8종을 편집기만으로 만들기 |
| 3-3 | 아이콘: 아이콘 고르기, 편집기·OSD에 표시 | |
| 3-4 | 프리셋 4종과 새 기본 설정, `프리셋에서 페이지 추가` | |
| 3-5 | 온보딩 3단계, 넘패드 키 입력 확인 화면 | 처음 실행 시나리오 |
| 3-6 | 한국어·영어: UI 문자열, 트레이 메뉴, OSD, 코어 오류 메시지 | 영어로 전체 흐름 |

## 설계 메모

### 편집기 ↔ 코어

Tauri command:

- `get_config() -> Config`, `save_config(Config) -> Result<(), 오류>`: 코어 검증 결과를 그대로 돌려준다. 파일 감시가 같은 내용을 다시 읽어도 내용이 같으면 무시된다(2-1).
- `test_action(Action)`: 실행기에 넘겨 바로 실행해 본다. 결과는 기존 OSD 실패 표시로도 보인다.
- `list_apps() -> [{name, target, …}]`: `shell:AppsFolder`를 열거해 일반 앱과 스토어 앱을 함께 준다. 스토어 앱은 `shell:AppsFolder\<AUMID>`.
- `start_hotkey_recording()` / 이벤트 `hotkey://recorded`: 아래 참고.
- 파일·폴더 고르기: `tauri-plugin-dialog`.

설정 타입은 Rust(`config.rs`)와 TypeScript에 둘 다 있어야 한다. 손으로 맞추지 않도록 Rust 타입에서 TypeScript 타입을 생성하는 방법(`ts-rs` 등)을 3-1에서 정한다.

### 자동 저장과 되돌리기

편집기 안에서 설정 전체를 상태로 들고, 바뀔 때마다 0.3초 모아서 `save_config`. 되돌리기는 편집기 안의 이전 상태 목록(최대 50개)으로 한다. 검증에 실패한 상태는 저장하지 않고 입력란 옆에 이유를 보인다(예: 빈 단축키).

### 단축키 녹화

브라우저의 `keydown`으로는 Win 조합을 녹화할 수 없다(Win+D는 OS가 먼저 처리한다). 그래서 코어 훅에 **녹화 모드**를 둔다.

- 녹화 중에는 주입이 아닌 모든 키를 막고(앱에 전달하지 않음) 편집기로 보낸다.
- 보조 키가 아닌 키가 눌리면 끝낸다. Esc만 누르면 취소. 5초 동안 아무 키도 없으면 자동 취소(키가 막힌 채로 남지 않게).
- 가짜 Shift(스캔 코드 0x200 비트)는 무시한다 (M1 실측).
- 넘패드 키는 녹화하지 않는다 (덱 키와 헷갈림).
- 결과는 `keys::name_of`로 이름 배열을 만든다.

### 아이콘

설정에는 Lucide 아이콘 이름(`"play"`, `"mic-off"` …)만 저장한다. 고르기 화면은 전체 목록을 검색하지만, 아이콘 전체를 넣으면 번들이 커지므로 OSD는 SVG를 이름으로 불러오는 방식을 3-3에서 정한다.

### 다국어

- UI 문자열은 `ko`/`en` 사전 두 개(라이브러리 없이 타입 있는 객체).
- 코어 오류 메시지는 지금 한국어 문자열이다. 오류 코드 + 값으로 바꾸고 문장은 UI가 만든다. 설정 오류(`ConfigError`)와 실행 오류(`ExecEvent::Failed`) 모두.
- 트레이 메뉴 문자열은 Rust에 두 언어로 둔다.

### 키 입력 확인 화면

온보딩 ②에서 넘패드를 눌러도 반응이 없으면 `넘패드를 눌러도 반응이 없나요?`로 들어가, 누른 키가 무엇으로 들어오는지 보여준다(노트북 내장 넘패드·넘패드 없는 키보드 안내). 진단용 훅 기록(`Trace`)을 쓴다.

## 미정·위험

- `ts-rs` 등 타입 생성 도구 선택 (3-1)
- Lucide 아이콘 불러오기 방식과 번들 크기 (3-3)
- 녹화 모드 중 훅이 키를 막는 동안 앱이 멈추면 키보드가 먹통이 된다. 5초 자동 취소와 Esc를 반드시 시험한다.
- `shell:AppsFolder` 열거는 COM 셸 API라 앱 목록이 많으면 느릴 수 있다. 처음 한 번 읽고 캐시한다.
